# TrackFerry TV 实施方案

首个里程碑是一份可侧载的原生 Android TV APK。在目标电视或盒子上，用遥控器打开一张 NAS 专辑，从中间选一首开始，拖动进度后歌词跟上，播完能接到下一首。电视可以独立播放，手机继续访问同一套曲库和歌词。Android TV 或 Google TV 之外的系统需要另外确认能否安装 APK。

## 端与服务的分工

| 层 | 职责 |
| --- | --- |
| Compose for TV | 使用 TV Material 和 Compose Foundation 的懒加载列表。页面围绕曲库、搜索、正在播放。遥控器负责方向、确认和返回，详情退出时还原焦点，列表由设备键导航。进度和歌词更新局限在播放器区域。 |
| Media3 | 同进程 `PlaybackService` 持有一个 ExoPlayer 和一个 `MediaSession`。Activity 通过 `MediaController` 读取状态和发命令，进出界面可重连。后台由媒体播放前台服务管理，处理音频焦点和输出切换。 |
| TV 本地存储 | 保存服务器配置和当前设备的播放快照。快照包含队列版本、条目顺序、当前条目、最近确认的位置和循环方式。曲目变化、暂停和定位完成即保存，播放中定期保存。恢复后等待用户继续播放。 |
| TrackFerry Go 服务 | 复用飞牛曲库、音源授权、Range 音频和歌词。提供面向播放端的版本化 API，负责鉴权、收藏和列表内容。浏览请求可分页，播放请求按完整列表解析。 |

APK 首版用 `MediaSessionService`。将来需要让 Android 系统或其他应用浏览媒体库时，再接 `MediaLibraryService`。Gradle 包装器、Android 插件、Compose 和 Media3 固定版本。支持 Android 6.0（API 23）及以上，分 `armeabi-v7a` 和 `arm64-v8a` 两个安装包发布。发版前按目标电视的系统、遥控器和解码能力实测确认。

## 曲库和队列契约

- 播放请求表达来源和起点。专辑、歌手、收藏、歌单使用来源 ID 和选中曲目，探索页发送当前这批条目的快照。搜索或历史的普通单曲使用独立队列。页面筛选和分页只影响可见内容。
- 同一曲目可出现多次，所以队列用独立的条目 ID 定位。队列状态包含顺序、当前条目 ID、循环模式和修订号。下一首和放到队尾是对当前修订的明确操作。快速切歌或重复请求时，旧响应只记入诊断。
- TV 的 ExoPlayer 是实际播放状态的来源。UI 区分准备、缓冲、播放、暂停、结束、失败。以播放器确认的位置恢复。取流失败优先重试同一个条目，失败超过预算时显示原因并允许手动跳过。
- 在线曲目需要可重新解析的音源标识。临时搜索键和 URL 仅用于当前解析。断网恢复时仍以同一条目重新解析。验证稳定后再做有界的下一曲预载，当前曲目始终有优先权。

## 歌词和进度

- 进度条和高亮读取同一个 Media3 `currentPosition`。正常播放时采样，暂停和缓冲时停在媒体位置，监听换曲和位置不连续事件立即校正。拖动预览单独显示，定位结算依据播放器回报。
- 歌词按曲目请求，迟到的歌词按条目匹配。普通 LRC 逐行、同时间戳的原文与译文一起高亮。词级高亮依赖来源提供的词级时间戳。偏移按曲存在服务端，网页和电视共用；电视不再有作用于所有歌曲的本机偏移。
- 频谱来自播放链里解码后的 PCM：按缓冲的呈现时间做 1024 点 FFT，分成 24 个对数频段，再按音频输出回报的播放位置取对应的一帧，所以画面和出声同步。不需要录音权限。暂停、定位或换曲时清空，频谱回到静止。
- 音效在 ExoPlayer 的音频处理链里做：先做前级衰减，再过五段双二阶滤波（60 Hz 低架、230/910/3600 Hz 峰值、14 kHz 高架），立体声预设最后加宽声场。系数和网页 Web Audio 用的是同一套公式，参数见 `web/src/eq.ts` 和 `Sound.kt`。不认识的格式原样通过；计算出错时，这一段原声放出并复位滤波器，不会中断播放。小爱音箱由音箱自己取流解码，服务端不转码，无法加音效。
- 屏幕默认显示当前句与相邻歌词，方向键能进出全屏歌词和待播队列。布局用正在播放的专辑封面和原有 TrackFerry 色调，确保坐在沙发上仍能看清选中项、唱到哪句，以及当前输出。

## 自动发现、配对和跨端

1. NAS 在局域网通过 mDNS/DNS-SD 发布 `_trackferry._tcp`。TV 打开连接页通过 Android `NsdManager` 搜索，列出服务，可选「手动连接」和「重新搜索」。独立的 TV HTTPS 端口默认是 `18562/TCP`。
2. 用户在已登录的手机管理页输入电视显示的 6 位码。配对码有效五分钟，同时绑定服务公钥、设备凭据和本次请求，只确认一次。电视记住服务公钥，服务器换地址后重新发现并核验，再连回。服务器密钥保存在 `data/private/tv-key.der`。
3. 设备凭据可读取曲库、音频和歌词，并可对飞牛曲目收藏、取消收藏或加入现有歌单。每台电视可单独撤销配对。电视用 Android Keystore 加密保存。电视连接只使用 HTTPS，已有的网页和小爱仍使用各自配置的地址。
4. 手机遥控阶段给设备分配稳定 ID，使用带命令 ID 和期望队列版本的控制请求。TV 回报当前条目与已确认的位置，服务端按修订拒绝过期状态。系统媒体会话负责 TV 上的媒体键，跨设备控制由 TrackFerry 的配对协议负责。
5. 接力携带队列及源端最后确认的位置。目标端确认已经起播后才暂停源端。超时或目标失败时源端继续，换歌或取消后旧确认失效。小爱按型号公开定位和回读能力，回读不足时显示估算或待确认。

发现验收先用默认的 NAS host 网络部署，电视接家庭 Wi‑Fi，屏幕上应直接出现 TrackFerry。候选下线要从列表移除。同一服务有多个网卡地址时只显示一次，VIP、证书或同名服务变化时仍按配对身份处理。桥接网络使用宿主机发布 DNS-SD，或走手动连接。首次扫描、扫描结束没有结果、找到但连不上、服务版本过旧，都有单独的界面状态。已经配对的 TV 优先连回原服务，发现另一台同名服务时保持待确认。

## 实施与放行

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| A · 原生播放底座 | `android-tv/`、可复现的 debug APK、内置合成测试音频和 LRC。遥控器可播放、暂停、切歌和定位。 | 先通过构建、lint 和歌词时钟回归。在电视或模拟器上验证媒体键、后台服务和方向键；实机测本机输出。 |
| B · 可日用的 TV | 局域网自动发现、设备配对、NAS 取流、完整曲库队列、搜索、歌词、播放恢复和签名 APK。 | 验证零地址输入接入、服务器换 IP、多服务器与组播不可达的回退。在至少一台目标电视跑整张专辑和长歌单，覆盖断网、进程重建、格式兼容和音频输出切换。 |
| C · 家庭播放端 | 手机可选择并控制电视，逐步开放从手机到电视、小爱与电视的接力。 | 验证同曲不同条目、连续投放、延迟或重放指令、目标失败和取消接力。 |

真机记录遥控器确认到出声的 P50 与 P95、切歌间隔、定位落点和歌词相对出声的偏差。先用连续混音专辑检验是否出现额外静音，再用已知时间戳的测试音频区分播放器时间差和 HDMI、蓝牙输出延迟。按电视型号、系统、格式和输出记录结果，明确支持范围后再标记为可日用。

Android 官方参考：[电视界面](https://developer.android.com/training/tv/playback/compose)、[后台媒体播放](https://developer.android.com/media/media3/session/background-playback)、[ExoPlayer 格式支持](https://developer.android.com/media/media3/exoplayer/supported-formats)、[NSD 服务发现](https://developer.android.com/reference/android/net/nsd/NsdManager)、[本地网络权限](https://developer.android.com/privacy-and-security/local-network-permission)。

## 手机遥控验收

1. 首次配对从「更多 → 电视」进入。电视显示六位码后，已登录的 PWA 会弹出配对窗。电视离线时从投放和「此刻」的设备列表移除，配对记录仍可在「更多 → 电视」查看和解除。
2. 已配对电视首次上线时，两个选择器同时切到电视。手动改选后，在线回报不会覆盖选择。「此刻」与曲库和搜索的「播放到」始终显示同一台设备。电视关闭且没有后台播放后，自动回到本机。
3. 用曲库或搜索投放，再到「此刻」查看实际曲目、进度、歌词、播放/暂停、切歌、循环、队列和 App 音量。电视首页上方左侧是正在播放，右侧是「随便听听」「随机专辑」「随机歌手」三个入口，下方是我的收藏和歌单。选中正在播放的封面，按确认打开播放页。播放页从当前封面生成背景，曲库歌曲可收藏，也可通过「更多操作 → 加入歌单」加入飞牛已有歌单。
4. 手机和电视互相接力时，目标端原位置附近开始播放后才暂停源端。从电视接到本机时浏览器必须允许这次点击起播。换歌或队列已改变时，旧接力请求无法暂停新曲。电视与小爱之间用曲库歌曲测试，支持定位的音频可按估算进度接续；小爱仅取流却没有确认播放时，源端继续。音箱原生内容、在线音源或不支持定位的格式不参与小爱进度接力。
5. 拔网恢复同地址，以及服务器换 IP 后以原公钥重新发现。退出、重新打开 TV App 后检查已保存的队列和进度，需手动继续播放。全屏歌词按 100 ms 调整这首歌的偏移，网页打开同一首歌应看到同样的值。再用实机的 HDMI、蓝牙和内置扬声器依次核对出声。

## 应用更新

服务器版本就是电视应用应有的版本。发版时 `scripts/publish.sh` 构建两个正式包，确认它们由电视发版密钥签名，再用更新签名密钥给 `trackferry-tv-<版本>-<abi>.apk` 签 `android/<abi>` 平台的签名，一并上传到 Release。

1. 电视在「设置 → 应用更新」用 `GET /api/tv/v1/app?abi=` 询问。服务器版本较新时，按「更新」发送 `POST`，服务器开始从 Release 下载并核对签名。电视每 1.2 秒询问一次进度；服务器重启后忘了这项任务，电视会重新发起。
2. 服务器报告就绪后，电视从 `GET /api/tv/v1/app/apk?abi=` 下载。响应头里的校验值必须和就绪时给出的相同，下载完再算一遍 SHA-256。不一致的文件会被删除。网络中断最多重试三次。
3. 文件交给系统的 PackageInstaller。还没允许安装应用时，电视打开系统设置；允许后不用再按，自动继续。系统的确认画面由系统显示。签名冲突、空间不足、系统不兼容都有各自的提示。离开「设置」页面不会中断更新。
